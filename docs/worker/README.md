# Перевіряльник здачі ДЗ

## Картка ролі
- Роль: перед відкриттям PR здачі перевіряє чернетку файлу здачі домашки за чеклістом курсу (C1–C9: поля, заглушки, посилання на SHA, повні адреси, `/api/health`, секрети, синтетичні дані, інструкції у файлі, пояснення кожного FAIL) і пише звіт «рядок → що не так → як виправити».
- Для кого: розробник агенції в курсі (моя власна рутина: за WS9–WS10 саме ці помилки знімали бали в здачах — заглушки, `blob/main`, короткі `#53`, непояснені FAIL, health на іншому хості).
- Тригер: людина в чаті (`/submission-checker data/<набір>`) або без людини — `./run.sh data/<набір>` (`claude -p`, можна з cron перед дедлайном).
- Канал результату: датований звіт `out/YYYY-MM-DD Перевірка <набір>.md` + JSON запуску `out/runs/<час>.json` + коротка відповідь у чаті.
- Ніколи не робить: не відкриває PR і не пише `@coderabbitai review`; не змінює файл здачі, дані, скрипти, правила й власні налаштування; не ходить у мережу (`WebFetch`, `curl`, `gh`); не читає `tests/` (там очікувані вердикти) і `.env*`; не повторює знайдені секрети у звіті.
- Шлях: 1 — Claude Code на власній підписці (особисте використання).

## Межі
- Де записано: `.claude/settings.json` (allow / deny) + `--permission-mode dontAsk` і `--allowedTools` у `run.sh`; правила ролі — `AGENTS.md` і `.claude/skills/submission-checker/SKILL.md`.
- Дозволено: `Skill(submission-checker)`, `Agent(submission-verifier)`, `Bash(node scripts/check-submission.mjs *)`, `Read` / `Grep` / `Glob` у теці, `Edit(/out/**)`.
- Заборонено: `Read`/`Grep`/`Glob(/tests/**)`, `Read(.env*)`, `Edit` будь-чого поза `out/` (`data/`, `scripts/`, `references/`, `tests/`, `.claude/`, `AGENTS.md`, `CLAUDE.md`, `run.sh`), `WebFetch`, `WebSearch`, `Bash(curl|wget|gh|rm|git push|git commit …)`, `node --test`.
- Перевірено на ділі: запуск 16:39 модель спробувала `node scripts/check-submission.mjs …; echo "EXIT=$?"; ls out/` — `dontAsk` відхилив (не збігається з дозволом), працівник чесно поставив «НЕ ПЕРЕВІРЕНО» без вигаданих знахідок (`docs/worker/runs/2026-11-16T16-39-21*`).

## Перевіряльник і людина в контурі
- Хто перевіряє: субагент `submission-verifier` (`.claude/agents/submission-verifier.md`) у чистому контексті, лише читання (Read, Grep, Glob, Bash — лише скрипт). Оркестратор передає йому тільки шлях до набору й чекліста, без своїх знахідок; перевіряльник сам запускає скрипт і **вибірково звіряє кожну знахідку з сирим файлом** (і шукає пропущене). Розійшлися — стан НЕ ПЕРЕВІРЕНО з обома версіями.
- Рахує код, а не модель: `scripts/check-submission.mjs` — детерміновані перевірки C1–C9, таблиця + `###JSON###`, код виходу 0 / 1 / 2.
- Що лишається людині: виправити файл здачі, відкрити посилання (працівник у мережу не ходить), звірити зміст доказів, відкрити PR здачі й попросити рецензію.
